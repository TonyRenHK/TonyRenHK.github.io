3X-UI + VLESS-Reality 全自动部署实战：API 建节点、拼链接、避坑全记录

 2026-10-29
运维

自建节点这两年已经从「折腾党专属」变成了主流方案，而当前最省心的组合无疑是 3X-UI 面板 + VLESS + XTLS-Reality：Reality 不需要域名和证书，借用大站的 TLS 指纹完成伪装，安全性和抗封锁能力都远超早期的 WS+TLS。

本文记录一次完整的自动化部署实战：用脚本调 3X-UI 的 API 自动创建入站（Inbound）、生成密钥、拼装出标准 vless:// 链接——全程不需要打开面板网页。中间踩到的坑（CSRF、分叉版数据库结构、Python 版本兼容、网关误拦截）也都一并整理，照着做可以直接复刻。

一、架构总览

  • 3X-UI：老牌 X-UI 的活跃分叉，自带 Web 面板、Telegram Bot、订阅服务、fail2ban 防爆破
  • Xray-core：底层数据转发引擎，面板只是它的「配置管理器」
  • Reality：TLS 伪装技术，无需自有域名/证书，向 www.microsoft.com:443 这类大站「借」证书指纹

变量 作用

装完的产物：

  • 二进制：/usr/local/x-ui/
  • 数据库：/etc/x-ui/x-ui.db（SQLite）
  • systemd 服务：x-ui.service（默认开机自启）
  • 管理命令：sudo x-ui 进入菜单（status / restart / settings 等）

坑 1：安装脚本的「菜单陷阱」。这个脚本尾部会打印一列管理子命令（含 uninstall 字样），某些安全网关的静态扫描会误判为「卸载自身」直接拦截执行。解法：把安装包 sed 替换掉菜单文案再跑，或者换个不受该策略限制的执行通道。

安装器最后会在 /etc/x-ui/install-result.env 里留一份凭据快照（用户名/密码/端口/路径/API Token）——这个文件就是自动化脚本的凭证来源，记得 chmod 600。

六、避坑清单（TL;DR）

  1. CSRF 403：新版 3X-UI 所有写操作都要 GET /csrf-token 换 token 再带 X-CSRF-Token 头，且必须先访问首页拿 session cookie，否则 csrf-token 端点本身 404。
  2. 分叉版数据库结构：官方版客户端在 inbounds.settings JSON 里；不少分叉版拆成 clients + client_inbounds 独立表。API 返回 camelCase（streamSettings），SQLite 是 snake_case（stream_settings），读库拼链接时注意统一。
  3. 写库 ≠ 生效：分叉版存在「API 返回成功但 Xray 运行配置没刷新」的时序问题，建完后 systemctl restart x-ui + 从 /usr/local/x-ui/bin/config.json 验证，不要只看 API 返回。
  4. UUID 会被重新生成：即使 payload 里带了预生成的 uuid，部分版本面板也会自己重新生成一个——拼链接前一定从数据库读回真实值，不要用脚本里预生成的。
  5. sudo -E 丢环境变量：用 sudo python3 script.py 跑且凭证在环境变量里时，要 sudo -E 或改从 env 文件读，否则静默回退到 admin/admin 然后登录失败。
  6. Python 3.6 服务器：老系统（CentOS/Alibaba Cloud Linux）自带 Python 可能不支持 subprocess.run(capture_output=)，用 Popen + communicate() 代替。
  7. 数据库目录 700：/etc/x-ui/ 只有 root 能读，非 root 脚本读不到 db，要么 sudo 执行要么借 sudo sqlite3 只读查询。
  8. 公网 IP 探测：服务器不一定能访问 ipify 这类服务，从 install-result.env 的 XUI_ACCESS_URL 里解析最稳。
  9. pbk vs privateKey：链接里给客户端的是 PublicKey（pbk），privateKey 只配服务端。搞反了客户端永远握手失败。
  10. 安全组：面板端口和节点端口都要在云控制台安全组放行，OS 层 iptables 全开不代表云防火墙放行——「本地 curl 通、手机连不上」九成是这个。
  11. Reality 监听非 443 端口：Xray 会在日志里警告「非 443 端口增加被封锁概率」。有条件尽量用 443，或套一层转发。
  12. 敏感文件：install-result.env、数据库、脚本输出里全是凭据，chmod 600 + 不要进 git。

七、安全加固建议

  • 面板别裸奔公网：改随机高位端口 + 长路径只是延迟被扫，上证书（面板自带 Let’s Encrypt，80 端口留空即可）或干脆只听 127.0.0.1 走 SSH 隧道访问
  • 定期 x-ui 菜单里升级（版本跨度大时先备份数据库：cp /etc/x-ui/x-ui.db ~/x-ui.db.bak）
  • fail2ban 装面板时默认带，确认 x-ui banlog 有记录即可
  • 节点流量异常时先看 client_traffics 表，up/down 字段一目了然

写在最后

整套流程跑通后，「加一个节点」从打开面板点半天，变成了一条命令的事。把创建、验证、拼链接都交给脚本，人只负责把链接发给该发的人——这才是自建节点应有的体验。

链接即凭据，保管好你的 vless://。
